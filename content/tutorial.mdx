# Zero-Effort Regression Testing in Go: Turning API Traffic into Golden Master Tests with Keploy

Writing integration tests for Go microservices usually means writing brittle mock structs, custom HTTP transports, and synthetic stubs that drift from reality the moment an upstream API updates.

**Keploy flips the script**: it records real API traffic and external dependencies transparently at the Linux socket layer, converting live requests into golden master test cases and deterministic offline mocks—with **zero changes to your Go code**.

In this guide, we take a real Go application that calls an external REST API, record live traffic, inspect the auto-generated YAML tests, replay them completely offline, and witness Keploy catch a regression in seconds.

## What We're Actually Doing

To understand Keploy, you need a mental model of where it sits during development:

<ArchitectureDiagram />

### Traditional Testing vs. Keploy Workflow

* **❌ Traditional Workflow**: Write handler &rarr; boot dependencies &rarr; curl manually &rarr; hand-write `_test.go` with mock structs &rarr; update mocks whenever APIs change.
* **✅ Keploy Workflow**: Run app with `keploy record` &rarr; curl normally &rarr; Keploy captures tests & mocks &rarr; replay hermetically with `keploy test`.

<WhyItMatters concept="Zero Code Intrusion">
Keploy requires <strong>zero changes to your Go code</strong>. You do not import an SDK, wrap handlers in middleware, or alter application state. Keploy operates directly at the operating system network socket layer.
</WhyItMatters>

## Prerequisites

Before starting, confirm your local environment meets these requirements:

* **Go Compiler**: Go `1.20+` installed (`go version`).
* **Linux Kernel or WSL2**: Linux kernel 5.10+ (Ubuntu 22.04+ recommended) with `tracefs` mounted.
* **Keploy CLI**: Keploy v3.6+ installed (`curl -O https://keploy.io/install.sh && bash install.sh`).
* **cURL**: Standard HTTP command line utility.

<Callout type="tip" title="Windows Developers Note">
Keploy's engine uses Linux eBPF tracepoints (`sys_socket`). On Windows, run Keploy inside WSL2 Ubuntu 22.04 for native performance.
</Callout>

<Collapse title="Under the Hood: How Keploy Records via eBPF & Virtual DNS" badge="Deep Dive">
When starting in record mode, Keploy configures four transparent mechanisms:
1. **eBPF Socket Hook**: Attaches tracepoints to the Linux kernel socket subsystem (`sys_socket`).
2. **Virtual DNS Server**: Runs an internal DNS resolver on port `26789` to intercept domain name lookups (`pokeapi.co`).
3. **Ingress Forwarding**: Intercepts port `8080` and proxies traffic to the app's internal socket.
4. **App Supervisor**: Spawns and manages the process supplied via `-c './http-pokeapi'`.
</Collapse>

### Key Elements of Generated Artifacts

* **`spec.req`**: The exact inbound HTTP request captured from curl.
* **`spec.resp`**: The golden master response returned by your Go code (status code, headers, JSON body).
* **`spec.assertions.noise`**: Keploy **auto-detected** that the HTTP `Date` header changes on every execution and excluded it from assertions so dynamic timestamps never cause test failures.
* **`mocks.yaml`**: Outbound HTTP requests to PokéAPI captured during recording. During retests, Keploy serves responses directly from this file.

<section id="things-that-surprised-me">
## Things That Surprised Me (DevRel Insights)

When running Keploy in real developer environments, key platform behaviors emerged:

<Collapse title="1. Windows Defender & WSL2 Kernel Support" badge="Windows / WSL2">
Direct execution of raw Windows binaries can trigger heuristic antivirus flags due to packet capture drivers. Running Keploy inside **WSL2 (Ubuntu 22.04 LTS)** gives full Linux eBPF kernel support with zero false positives.
</Collapse>

<Collapse title="2. The musl vs glibc Requirement on Alpine" badge="Containers">
Keploy's eBPF agent is compiled against `glibc` (`/lib64/ld-linux-x86-64.so.2`). Minimal Alpine Linux environments lack glibc and fail with `cannot load agent`. Use Ubuntu, Debian, or Fedora environments.
</Collapse>

<Collapse title="3. Automatic Noise Classification" badge="Smart Assertions">
We did not configure custom ignore rules for volatile headers. Keploy automatically flagged `Date` as dynamic noise and omitted it from assertions.
</Collapse>

<section id="troubleshooting">
## Troubleshooting Guide

<Callout type="warning" title="neither debugfs nor tracefs are mounted">
**Symptom**: <code>failed to attach the tracepoint hook on sys_socket: neither debugfs nor tracefs are mounted</code><br/>
**Fix**: Mount tracefs in your Linux/WSL terminal:
<pre><code>sudo mount -t tracefs nodev /sys/kernel/tracing
sudo mount -t debugfs nodev /sys/kernel/debug</code></pre>
</Callout>

<Callout type="warning" title="Port Already in Use (8080)">
**Symptom**: <code>listen tcp :8080: bind: address already in use</code><br/>
**Fix**: Terminate old application processes running in the background:
<pre><code>sudo fuser -k 8080/tcp || pkill -f http-pokeapi</code></pre>
</Callout>

<Callout type="warning" title="Replay Times Out / App Starts Slowly">
**Symptom**: Keploy attempts to send requests before the Go server finishes binding.<br/>
**Fix**: Increase the <code>--delay</code> flag (e.g. <code>keploy test -c "./http-pokeapi" --delay 10</code>).
</Callout>
